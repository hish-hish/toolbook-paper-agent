# D2 大模型接入：国内云端 API（DeepSeek / Qwen）

> 一句话：不自购"大脑"，而是租用云端的大脑——把问题发给 DeepSeek/Qwen 的服务器，按用量付少量费用。

## 1. 这个决策点解决什么问题？

项目里多处需要"理解语言、生成文字"的能力：改写查询、判断答案是否有原文依据、组织最终回答。这些活由**大语言模型（LLM）**干。问题是：模型跑在哪？

- **云端 API**：模型在厂商机房，你通过网络调用。
- **本地部署**：模型下载到自己电脑，用自己的显卡跑。

## 2. 云端 API 是什么（大白话）

像点外卖：你不用自己养厨师（买显卡、装模型），只要打电话（发 HTTP 请求）报菜名（提示词），厨房做好送回来（模型回复）。

三个关键名词：
- **API Key**：你的会员卡号，证明"费用记我账上"。放在 `.env` 文件里，**绝不能写进代码或上传 GitHub**。
- **Token**：计费单位，约等于 0.5–0.75 个汉字或 0.75 个英文单词。输入、输出分别计费。
- **OpenAI 兼容接口**：行业统一的"点单格式"。DeepSeek、Qwen、硅基流动都用同一格式，换服务商只需改配置里的网址和模型名，代码不动。

## 3. 为什么选它（优势）

| 优势 | 说明 |
|---|---|
| 便宜到可忽略 | DeepSeek 约 ¥1–2/百万 token。本项目 3 本书 + 比赛期几百次问答，总费用预计 **几元人民币** |
| 不占显卡 | 你的 8GB 显存留给 MinerU（D3）和 reranker（D10）这两个必须本地跑的模型 |
| 效果强 | "逐句核对答案与原文"是精细活，云端大模型比本地 7B 小模型可靠得多 |
| 接入快 | 十几行代码调通，12 天工期友好 |

落选方案：本地 Ollama 需要大显存且小模型核验易出错；海外 API 贵且有网络门槛。资料不涉密，上云无顾虑。

## 4. 在本项目中怎么工作（工作环节）

LLM 在流程中被调用 4 次（都在 D1 的图节点里）：

1. **查询改写**：输入用户问题 → 输出中英双语检索关键词。
2. **章节树兜底**（仅导入无目录文档时，D5）：输入文档文本 → 输出提议的章节结构。
3. **归纳核验**（D11）：输入"答案句子 + 原文片段" → 输出"有依据/无依据 + 依据位置"。
4. **答案生成**：输入核验过的材料 → 输出带引用的最终回答。

每次调用都是：`组装提示词 → 发请求 → 收回复 → 解析结果`，失败自动重试 1–2 次。

## 5. 初学者常见问题

- **Q：DeepSeek 能做 embedding 吗？**
  A：**不能**。DeepSeek 官方只有对话模型。embedding 另配（D8，推荐硅基流动 bge-m3 免费）。
- **Q：比赛现场断网怎么办？**
  A：LLM 依赖网络，这是已知风险。预案：提前彩排 + 录屏备份（计划书第 7 节）。
- **Q：费用会不会失控？**
  A：设置用量上限；3 本书规模下正常用一个月也就几块钱。
