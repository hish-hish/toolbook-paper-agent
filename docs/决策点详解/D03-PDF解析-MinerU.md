# D3 PDF 解析：MinerU

> 一句话：MinerU 是一个"看得懂版面的机器人"，把 PDF 这种排版文件还原成带章节标题、公式、表格的结构化文本。

## 1. 这个决策点解决什么问题？

PDF 的本质是**一堆"在坐标(x,y)画这个字"的排版指令**，它不知道什么是段落、什么是标题。直接抽文本会遇到：

- 双栏论文被按"左一行右一行"错误拼接；
- 公式变成乱码；
- 表格散成一地碎片；
- 标题和正文混在一起，分不清章节。

而你的核心需求是"按章节号索引"，所以**解析质量直接决定整个项目的上限**。

## 2. MinerU 是什么（大白话）

上海 AI 实验室开源的 PDF 深度解析工具。它不像传统库那样"抠字"，而是先用视觉模型**看版面**：

```
PDF 页面 → 版面检测（哪里是标题/正文/表格/公式/图片）
        → 分区识别（文字 OCR、公式转 LaTeX、表格转结构化数据）
        → 按正确阅读顺序拼装
        → 输出 Markdown + content_list.json（每块内容带页码坐标）
```

- **Markdown**：带 `#`/`##` 标题层级的纯文本，章节结构一目了然。
- **content_list.json**：每个内容块的类型、文本、**所在页码**——这是"原文核对能定位到页"的关键。
- **pipeline 后端**：MinerU 的传统视觉模型流水线，8GB 显存可跑（另一种 VLM 后端要更大显存，不用）。

## 3. 为什么选它（优势）

| 优势 | 说明 |
|---|---|
| 学术 PDF 解析质量第一梯队 | 双栏论文、公式、表格都能正确处理，模块B的论文解析直接受益 |
| 输出自带结构 | 标题层级 → 章节树（D5）；页码 → 出处定位（D11），省掉大量自研规则 |
| 开源免费 | 本地跑，不限量 |

代价：要下载数 GB 模型、Windows 环境配置有坑、吃显存。所以计划书设了**止损条款：配置限时 1 天，失败降级 PyMuPDF+规则**（解析器做成可替换接口，下游不受影响）。

## 4. 在本项目中怎么工作（工作环节）

**导入阶段（模块A）与论文上传（模块B）共用：**

1. 用户提交 PDF → 判断是否扫描版/文字版。
2. MinerU pipeline 解析 → 得到 Markdown + content_list.json。
3. 从 Markdown 标题层级提取章节树（D5 接手）。
4. 每个内容块记录页码，存入 SQLite（D13）。
5. **释放显存**——查询阶段要把显存让给 reranker（D10），两者不同时驻留。

## 5. 初学者常见问题

- **Q：8GB 显存够吗？**
  A：pipeline 后端够；VLM 后端不够，别选错。
- **Q：模型从哪下？**
  A：首次运行自动下载，国内可配置从 ModelScope（魔搭）拉取，速度快。
- **Q：装不上怎么办？**
  A：触发止损，换 PyMuPDF（纯 Python 库，pip 即装）+ 书签目录/字体规则。功能降级但流程不断。
