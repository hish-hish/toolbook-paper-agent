# D11 原文核验：两级混合（机械匹配 + LLM 逐句核对）

> 一句话：这是本项目的招牌——答案出口前设两道安检：摘抄必须和原文一字不差（机器比对），归纳必须句句有原文依据（LLM 核对），不合格的当场剔除或回炉重查。

## 1. 这个决策点解决什么问题？

LLM 有"幻觉"毛病：可能把检索到的内容记串、夸大、甚至编造。你的需求明确写着"**对给出的章节号进行原文核对，最后返回核验过的内容**"。普通 RAG 项目只附出处不核对——这正是你比赛差异化的核心。

## 2. 两级核验是什么（大白话）

答案分两种成分，用两种安检：

**第一级：机械核验（管"原文摘录"）**
- 答案里凡是声称"原文说"的摘录，拿去做**精确子串匹配**：在对应章节原文里找这段话（先归一化空格/标点/全半角）。
- 找得到 → 盖章"机械核验通过"；找不到 → 直接丢弃。
- 特点：**100% 可靠、零成本**，机器比对不存在看走眼。

**第二级：LLM 逐句核验（管"归纳总结"）**
- 归纳性答案拆成句子，每句连同原文片段交给 LLM 裁判："这句话有没有原文依据？依据在哪？"
- 有依据 → 保留并强制挂引用标记；无依据 → 剔除该句。
- 特点：允许返回"人话总结"，但每句话都被原文锚住。LLM 裁判也可能看走眼，所以摘录部分永远走第一级兜底。

**回炉机制**：核验后材料不够回答问题 → 沿 D1 的回头路换查询词重检索（最多 2 次）→ 仍不行 → **拒答**："资源库未覆盖该知识点"，并列出已检索范围。宁可少答，不可错答。

## 3. 为什么选两级混合（优势）

| 优势 | 说明 |
|---|---|
| 可靠性分层 | 最关键的"原文摘录"用零误差的机械匹配；灵活的"归纳"用 LLM 但逐句锚定 |
| 可展示 | 每条内容带核验徽章（机械✓ / LLM✓），评委肉眼可见你的特色 |
| 防幻觉闭环 | 核验→重检索→拒答，超纲问题不硬答，可信度拉满 |

落选方案：纯机械只能返回摘抄不能总结；纯 LLM 核验自身不可 100% 保证；不核验违背需求。

## 4. 在本项目中怎么工作（工作环节）

```
top5 父块 + 问题
  → LLM 生成答案（要求：摘录加[引]标记，归纳每句标引用）
  → 拆句分流：
      摘录句 → 归一化 → 在章节原文中子串匹配 → 通过/丢弃
      归纳句 → LLM裁判(句, 原文) → 有依据(挂引用)/剔除
  → 剩余材料够答题？
      够 → 输出：答案 + 核验徽章 + 原文摘录块 + 出处目录
      不够 → 重试<2次？ → 回D1重检索 / 拒答
```

**最终输出格式**（UI 呈现）：
1. 归纳答案（每句带引用角标）
2. 核验过的原文摘录（标"机械核验✓"）
3. 出处目录：《书名》→ 章 → 节 → 页码（系统编号带徽标）

## 5. 初学者常见问题

- **Q：归一化是什么？**
  A：比对前把全角/半角、多余空格、中英文标点统一，避免"一个字不差却因为标点判失败"。
- **Q：LLM 核验不是很贵？**
  A：每次问答多 1–2 次调用，DeepSeek 价格下每次问答总成本不到几分钱。
- **Q：评委问"核验本身错了怎么办"？**
  A：摘录层零误差兜底 + 核验徽章透明展示 + 拒答路径，三层防线；这是设计上的诚实，比声称"绝不出错"更加分。
