# D10 重排序：bge-reranker-v2-m3（本地）

> 一句话：检索是"广撒网"捞回 30 个候选，reranker 是"精挑细选"——逐字阅读问题和每个候选，重新排出真正最相关的 5 个。

## 1. 这个决策点解决什么问题？

D7 的混合检索为了快，用的是"粗筛"：BM25 数词频、向量比距离，都没有**真正读懂**问题和片段。捞回的 top-30 里常混着"字面像但意思不对"的噪声。如果直接拿给 LLM 写答案，噪声会污染答案、加重核验负担。

## 2. Reranker 是什么（大白话）

- 检索模型（bi-encoder）：问题和片段**各自**翻译成向量再比距离——快，但没交互。
- 重排模型（cross-encoder）：把"问题 + 片段"**拼在一起**喂进模型，让它像阅卷老师一样逐字对照打分——准，但慢，所以只用于精挑少量候选。

bge-reranker-v2-m3 是 BAAI 开源的中英多语言重排模型，和 D8 的 bge-m3 同家族，约 2GB，你的 3060 Ti 跑得动。

## 3. 为什么选它（优势）

| 优势 | 说明 |
|---|---|
| 免费开源 | 本地跑，查询不限量、不联网 |
| 中英效果好 | 覆盖你的中英混合资源库 |
| 提升立竿见影 | RAG 公认的高性价比增强：top-5 质量上去了，核验通过率和答案质量跟着涨 |
| 答辩有实验点 | "加/不加 rerank"的命中率对比是现成的消融实验 |

## 4. 在本项目中怎么工作（工作环节）

```
RRF融合后的 top 30 父块
  → 逐对打分：reranker(问题, 父块文本) → 相关度分数
  → 按分数重排 → 取 top 5
  → 交给核验（D11）
```

**显存调度（8GB 的关键约束）**：
- MinerU（导入时）和 reranker（查询时）**不同时加载**。
- 方案A：按需加载/释放——导入结束卸载 MinerU，首次查询加载 reranker 常驻。
- 方案B（更稳）：reranker 跑 CPU。3 本书、每次只排 30 对，CPU 也就几秒，比赛演示可接受，还彻底避免显存冲突。
- 实现时先试 A，不顺就切 B，接口不变。

## 5. 初学者常见问题

- **Q：为什么不直接用云端 rerank API？**
  A：也可以（硅基流动/阿里都有），但你已选本地版：免费、离线可用、少一个网络依赖。现场断网时它是少数还能工作的环节。
- **Q：30 进 5 出，数字怎么定？**
  A：起步值，评测集上调。候选太少怕漏，太多浪费核验成本。
