# D12 交互界面：Streamlit（内核与 UI 分离）

> 一句话：Streamlit 让你用纯 Python 几十行代码变出一个网页界面——上传文件、聊天框、侧边栏目录树全是现成组件，不用学任何前端。

## 1. 这个决策点解决什么问题？

Agent 内核（解析/检索/核验）是命令行里的 Python 函数，但比赛演示需要**看得见的界面**：拖拽上传 PDF、浏览书籍目录、聊天式提问、展示核验徽章。界面方案从"零界面"到"专业前后端"有一整条光谱。

## 2. Streamlit 是什么（大白话）

一个"Python 脚本即网页"的框架：

```python
import streamlit as st

st.sidebar.title("资源库")          # 侧边栏
uploaded = st.file_uploader("上传论文PDF")  # 上传组件
question = st.chat_input("就论文知识点提问")  # 聊天输入框
st.chat_message("assistant").write(answer)   # 聊天气泡
```

运行 `streamlit run app.py`，浏览器自动打开一个网页。**你写的每一行还是 Python**，没有 HTML/CSS/JavaScript。

**内核与 UI 分离**：所有核心逻辑（解析、检索、核验）写成独立的 Python 包，Streamlit 只是调用它们的一层薄壳。好处：调试/批量实验可以直接命令行调内核；以后想换专业前端也不用重写逻辑。

## 3. 为什么选它（优势）

| 优势 | 说明 |
|---|---|
| 零前端门槛 | 你是 Python 初学者也能一天搭出像样的界面 |
| 组件齐全 | 文件上传、聊天、侧边栏树、进度条、徽章标签都有现成的 |
| 演示够用 | 答辩投屏效果不输专业前端，12 天工期下性价比最高 |
| 不锁死未来 | 内核分离，赛后想升级 FastAPI+Vue 随时可换壳 |

落选方案：CLI 演示效果差；Gradio 布局自由度略低；FastAPI+前端要学一套前端技术栈，偏离比赛重心。

## 4. 在本项目中怎么工作（工作环节）

**页面布局（初步设想）：**
```
┌──────────────┬───────────────────────────────┐
│ 侧边栏        │ 主区                           │
│ · 资源库列表  │ Tab1 资源库查询：               │
│ · 章节目录树  │   关键词/章节号输入 → 核验答案   │
│ · 导入按钮    │ Tab2 论文问答：                 │
│   (docx/pdf/ │   上传PDF → 显示论文目录         │
│    epub)     │   → 聊天提问 → 答案+资源库出处   │
│ · 导入进度条  │ 每条答案：引用角标+核验徽章+目录 │
└──────────────┴───────────────────────────────┘
```

**工作流：**
1. 侧边栏上传书籍 → 调内核导入管道（D3–D6）→ 进度条 → 目录树刷新。
2. Tab1 输入关键词或章节号 → 调查询流程（D7–D11）→ 渲染带徽章的答案。
3. Tab2 上传论文 → 内核解析并暂存会话 → 展示论文目录 → 用户提问 → 跨库查询 → 答案附资源库目录。

## 5. 初学者常见问题

- **Q：Streamlit 每次交互都会重跑脚本？**
  A：是的，这是它的模型。用 `st.session_state` 保存论文解析结果、聊天记录等跨交互状态，别每次重算。
- **Q：能多人同时用吗？**
  A：比赛单机演示足够；它不是高并发服务器，别拿去部署公网服务。
