# D7 检索方式：BM25 + 向量混合 + RRF

> 一句话：同时派两个"查找员"——一个按字面关键词找（BM25），一个按意思相近找（向量），再把两份推荐名单公平合并（RRF）。

## 1. 这个决策点解决什么问题？

"根据关键词/问题找到书里对应的内容"是本项目的心脏。查找有两种哲学：

- **字面匹配**：你查"傅里叶变换"，我就找包含这几个词的段落。
- **语义匹配**：你查"怎么把信号拆成不同频率"，我找**意思相近**的段落，哪怕它一个字都没提"傅里叶"。

两种各有盲区，所以都要。

## 2. 名词解释（大白话）

- **BM25**：经典关键词打分算法（Elasticsearch 同款）。一个词在某段出现越多、在全库越罕见，这段得分越高。中文要先用 jieba 分词。**优点：术语、符号、公式编号查得极准；缺点：不懂同义词，"CNN"查不到"卷积神经网络"。**
- **向量检索**：用 embedding 模型（D8）把文本变成一串数字（向量），意思相近的文本向量距离近。查问题=算问题向量，找距离最近的块。**优点：懂改写、懂跨语言；缺点：专有名词有时反而不如字面匹配。**
- **RRF（倒数排名融合）**：合并两份名单的公平算法。不看原始分数（两路分数量纲不同没法直接比），只看**名次**：某块在 BM25 排第 2、向量排第 3，融合分 = 1/(60+2) + 1/(60+3)。两路都靠前的块最终靠前。

## 3. 为什么选混合（优势）

| 优势 | 说明 |
|---|---|
| 互补盲区 | 你的场景既有"按关键词查"（BM25 强项）又有"论文知识点提问"（向量强项），单一方案必偏科 |
| 跨语言有着落 | 英文论文提问查中文教材：向量侧天然支持；BM25 侧由 LLM 先把问题改写出中文关键词（查询改写环节） |
| 可解释 | BM25 那路能说出"命中了哪个词"，答辩演示时直观 |
| 业界公认最稳 | 混合+RRF 是当前 RAG 的标准答案，评委挑不出方法论毛病 |

## 4. 在本项目中怎么工作（工作环节）

```
用户问题
  → [LLM查询改写] 生成：原问题 + 中文关键词串 + 英文关键词串
  │
  ├─ BM25 路：关键词串 → jieba分词 → 词频打分 → 名单A（top 30）
  ├─ 向量路：原问题 → embedding → Chroma近邻搜索 → 名单B（top 30）
  │
  → [RRF融合] 按名次合并去重 → 候选 top 30
  → [reranker精挑]（D10）→ top 5 父块
  → 进入核验（D11）
```

另外保留一条**旁路**：用户直接输入章节号（如"3.2"）时不检索，直接查 SQLite 章节树取原文——这是"按章节号索引"需求的实现。

## 5. 初学者常见问题

- **Q：为什么不直接上 Elasticsearch？**
  A：3 本书几千个块，用轻量 `rank_bm25` 库或 SQLite FTS5 足够，ES 要起服务，违背"单机一键启动"原则。
- **Q：RRF 里的 60 是什么？**
  A：平滑常数，防止第 1 名权重过大，业界默认值，不用深究。
- **Q：两路结果打架听谁的？**
  A：都不听，交给 reranker（D10）读原文做最终裁决。
