# ToolBook-Paper Agent 云端部署指南

> 目标：把本应用部署到你的阿里云服务器（公网 IP `47.107.249.54`），用浏览器凭账号密码访问。
> **铁律：服务器上已有一个程序（agent-lab，端口 7860）在跑，全程绝不碰它、绝不重启服务器。**
> 本应用用 Docker 容器跑在 **端口 8501**，并设 **内存硬上限 600M**——即便内存吃紧，系统也只会杀本容器，不会波及现有程序。

---

## 0. 总览（先看懂再动手）

```
你的 Windows 电脑                          阿里云服务器（Ubuntu 24.04，1GB 内存）
┌─────────────────────┐                  ┌──────────────────────────────────────┐
│ 1. 打部署包 tar.gz   │  ── scp 上传 ──> │ 3. 解包到 /root/toolbook               │
│   （含代码+资源库，  │                  │ 4. 建 .env（填密钥+账号密码）          │
│    不含 2.2G 模型）  │                  │ 5. bash scripts/deploy_server.sh       │
│ 2. ssh 登录服务器    │  ── 密码自己输 ─>│    装Docker→建镜像→内存上限跑→探活     │
└─────────────────────┘                  │ 6. 阿里云控制台放行 8501 入方向        │
                                          │ 7. 浏览器 http://47.107.249.54:8501    │
                                          │    现有程序 7860 原样不动 ✓            │
                                          └──────────────────────────────────────┘
```

**为什么这样设计（关键决策）**
- **去 torch**：本地重排模型要 1–2GB 内存，服务器只有 1GB 装不下。改用**硅基流动云端重排 API**（`/v1/rerank`，同一个密钥），镜像里**不装 torch/sentence-transformers/mineru**，运行内存约 350MB，600M 上限够用。
- **Docker 内存硬上限**：`--memory=600m --memory-swap=600m` 把本容器关进「内存笼子」，超了只杀它自己，**现有程序绝对安全**。
- **不重启服务器**：现有程序是裸进程（没设开机自启），**一重启它就没了**。装 Docker、跑容器都不需要重启，全程不重启。
- **端口 8501**：避开现有程序的 7860，互不干扰。
- **密钥/密码不进代码**：只放服务器上的 `.env`，由 `--env-file` 注入容器；`.env` 已 gitignore，绝不提交、绝不贴聊天。

**命令在哪输入？**
- 标 **【本地】** 的：在你电脑的 **Git Bash** 里输入（开始菜单搜 “Git Bash”）。
- 标 **【服务器】** 的：先 ssh 登录服务器后，在 **SSH 会话**里输入。
- 标 **【阿里云控制台】** 的：在浏览器登录阿里云网页操作。

## 1. 【本地】打部署包

打开 Git Bash，逐条运行（第一条进入项目目录）：

```bash
cd "D:/Qoder CN workspace/toolbook-paper agent"

tar --exclude='.venv' --exclude='.git' --exclude='.env' \
    --exclude='models' --exclude='eval' --exclude='__pycache__' \
    --exclude='.pytest_cache' --exclude='.idea' --exclude='*.bak-*' \
    -czf ../toolbook-deploy.tar.gz .
```

- 产物：`D:/Qoder CN workspace/toolbook-deploy.tar.gz`（约 **90MB**）。
- **排除了什么**：`.venv`（本地虚拟环境）、`.git`、`.env`（你本地的密钥，**不上传**，到服务器另建）、`data/models`（2.2G 本地重排模型，云端用不到）、`data/eval`（跑分记录）、各种缓存与备份。
- **包含了什么**：全部代码（`src/`、`app.py`、`scripts/`、`Dockerfile` 等）+ 资源库（`data/library.db`、`data/chroma/`、`data/books/`、`data/papers/`）+ `.env.example` 模板。

检查包大小（可选）：
```bash
ls -lh ../toolbook-deploy.tar.gz
```

## 2. 【本地】上传部署包并登录服务器

仍在 Git Bash：

```bash
# 上传（会提示输入服务器密码，你自己输；约 90MB，视网速几十秒到几分钟）
scp ../toolbook-deploy.tar.gz root@47.107.249.54:/root/

# 登录服务器（同样你自己输密码）
ssh root@47.107.249.54
```

> 输密码时屏幕不显示字符，是正常的，输完回车即可。
> 登录成功后，命令提示符会变成服务器的（类似 `root@iZwz972gc1khg6lwtfe7uzZ:~#`）。**接下来的命令都在这个 SSH 会话里输入。**

## 3. 【服务器】解包

```bash
mkdir -p /root/toolbook
tar -xzf /root/toolbook-deploy.tar.gz -C /root/toolbook
cd /root/toolbook
ls -la          # 应能看到 app.py / src / Dockerfile / data / scripts 等
```

---

## 4. 【服务器】创建 .env（填密钥 + 账号密码）

```bash
cp .env.example .env
nano .env
```

在 nano 编辑器里，把三处填好（**密钥去硅基流动控制台拿，别贴给任何人**）：

```
SILICONFLOW_API_KEY=sk-你的真实硅基流动密钥
TOOLBOOK_AUTH_USER=hish
TOOLBOOK_AUTH_PASS=你的登录密码
TOOLBOOK_RERANK_BACKEND=api
```

- `TOOLBOOK_AUTH_USER` / `TOOLBOOK_AUTH_PASS`：浏览器登录用的账号密码。**两项都要填**，否则登录门关闭＝公网裸奔。
  - 你之前定的是 `hish` / `hish`——**这是弱密码，公网建议改强一点**（比如一串随机字母数字）。改这里即可，代码里不存密码。
- 填完保存退出 nano：**Ctrl+O → 回车 → Ctrl+X**。

> `.env` 只存在服务器上，不进镜像、不进 git。脚本会检查密钥非空、并提醒账号密码是否填全。

---

## 5. 【服务器】一键部署

```bash
bash scripts/deploy_server.sh
```

脚本会依次自动完成（**全程不重启服务器、不碰 7860**）：
1. 检查 `.env` 密钥、`data/library.db` 是否就位；记录部署前 7860/8501 端口状态。
2. 没装 Docker 就装 Ubuntu 自带的 `docker.io`（**不需要重启**）。
3. `docker build` 建精简镜像（**首次较久**：下载 python 基础镜像 + pip 装依赖；服务器内存小会用到 swap，慢属正常，见下方「构建内存」说明）。
4. `docker run` 启动容器：`--memory=600m --memory-swap=600m -p 8501:8501 --restart always --env-file .env -v /root/toolbook/data:/app/data`。
5. 探活 `http://localhost:8501/_stcore/health`，通过才算成功。
6. 复核：7860 仍在、8501 是本应用、容器内存上限生效。

看到 `==> 完成。浏览器访问 …` 即部署成功。

**构建内存说明（保护现有程序）**：服务器物理内存约 894M、可用约 380M，但有 **2GB swap** 兜底。pip 装的都是预编译 wheel（不编译大代码），构建峰值内存几百 M，会临时借用 swap，**不会触发系统 OOM 杀进程**。构建期间可另开一个 SSH 会话跑 `free -h` 观察。若你仍担心，可挑现有程序空闲时段构建。**运行期**容器被 600M 硬上限关住，绝对安全。

## 6. 【阿里云控制台】放行 8501 端口

服务器防火墙放行了还不够，**阿里云安全组**也要放行入方向 8501：

1. 浏览器登录 [阿里云控制台](https://ecs.console.aliyun.com) → 找到这台 ECS 实例。
2. **安全组** → **配置规则** → **入方向** → **手动添加**：
   - 端口范围：`8501/8501`
   - 授权对象（源）：`0.0.0.0/0`（允许任何 IP 访问；因有登录门，可接受。若想更安全，填你自己的公网 IP/32）
   - 协议：TCP，策略：允许
3. 保存。**无需重启实例。**

> 只放行 8501，**别动 7860 及其他现有规则**。

## 8. 日常运维（都在【服务器】SSH 会话里）

```bash
docker logs -f toolbook        # 实时看日志（Ctrl-C 退出查看，不停容器）
docker restart toolbook        # 重启本应用（不影响 7860）
docker stop toolbook           # 停止本应用
docker start toolbook          # 再启动
docker stats toolbook          # 看本容器实时内存/CPU（确认在 600M 内）
free -h                        # 看整机内存与 swap
ss -ltnp | grep -E ':7860|:8501'   # 确认两个程序都在监听
```

**更新代码后重新部署**：本地改完代码 → 重打 tar 包（第 1 步）→ scp 上传 → 服务器解包覆盖 → 再跑 `bash scripts/deploy_server.sh`（脚本会自动删旧容器、重建、重跑）。`.env` 与 `data/` 不会被覆盖丢失（解包不含 .env；data 若不想覆盖可单独保管）。

## 9. 安全与回滚

- **绝不重启服务器**：现有程序无开机自启，重启即丢失。本部署所有步骤都不需要重启。
- **完全移除本应用（不碰现有程序）**：
  ```bash
  docker rm -f toolbook          # 删容器
  docker rmi toolbook:latest     # 删镜像（可选，释放磁盘）
  ```
  删完 8501 不再监听，7860 原样。资源库文件仍在 `/root/toolbook/data`，需要时再跑脚本即可恢复。
- **密钥泄露应急**：若怀疑密钥外泄，去硅基流动控制台**重置密钥**，改服务器 `.env` 后 `docker restart toolbook`。
- **弱密码提醒**：`hish/hish` 仅适合临时演示；公网长期用请在 `.env` 改强密码后 `docker restart toolbook`。

## 10. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 脚本报「缺少 .env / 密钥为空」 | 第 4 步没填好，`nano .env` 补全密钥再跑 |
| 脚本报「缺少 data/library.db」 | 部署包没含资源库或解包路径不对；确认 `/root/toolbook/data/library.db` 存在 |
| 构建很久 / 卡住 | 首次下载基础镜像+依赖，慢属正常；另开 SSH 跑 `free -h`、`docker logs` 观察；只要 swap 在用就不会 OOM |
| 健康检查未通过 | 脚本会打印 `docker logs --tail 40 toolbook`；常见是密钥错（日志有 401）或 data 没挂载好 |
| 浏览器打不开 8501 | 多半是**阿里云安全组没放行**（第 6 步）；或容器没起（`docker ps` 看 toolbook 是否 Up） |
| 登录后资源库为空 | data 没挂载或 library.db 没传上来；`docker exec toolbook ls /app/data` 确认 |
| 提问报「未配置 SILICONFLOW_API_KEY」 | `.env` 密钥没注入；确认 `--env-file .env` 且密钥非空，`docker restart toolbook` |
| 担心内存波及现有程序 | 运行期容器有 600M 硬上限，`docker stats toolbook` 可证；现有程序 7860 不受影响 |

## 附：本应用云端运行参数一览

| 项 | 值 |
|---|---|
| 容器名 | `toolbook` |
| 端口 | `8501`（避开现有 7860） |
| 内存上限 | `--memory=600m --memory-swap=600m`（OOM 只杀本容器） |
| 重启策略 | `--restart always`（容器崩溃自动拉起；**主机重启不会自动起现有程序，故别重启主机**） |
| 重排后端 | `TOOLBOOK_RERANK_BACKEND=api`（硅基流动云端，免 torch） |
| PDF 解析 | 默认 PyMuPDF（云端不装 mineru） |
| 资源库 | 挂载 `/root/toolbook/data → /app/data`（不烤进镜像） |
| 密钥/账号 | `.env` 经 `--env-file` 注入（不进镜像、不进 git） |
| 登录门 | `TOOLBOOK_AUTH_USER/PASS` 都非空才开启 |
